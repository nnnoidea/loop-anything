# 网页工作台使用说明

侧栏标明当前页面属于“本地平台”还是“团队平台”。两个平台有独立的页面、运行和记录，本地运行和团队运行分别由各自平台管理，任务的具体执行机器仍由任务配置决定。

侧栏显示当前网页所属的本地平台或团队平台。打开「设置 → 常规」可填写远端服务器地址，使用 NAS 时可补充团队网页地址。新任务的默认运行平台可在「Agent 与启动器偏好」中单独设置。自动选择按已记录地址决定，两端都有地址时优先团队；已有 Run、Timeline 和会话继续由原平台处理。

工作台包含 Timeline、运行、监控和定时任务。规划托管有独立入口。「Loop」包含 Loop 库和 RSI for loop，Agent 通信用于查找 Agent 和处理协作请求。长期配置统一在「设置」中管理，包括远端服务器、防休眠、团队连接、接单 Agent 和通知出口。

网页用于阅读和运行操作。Agent 通过平台工具读写同一份数据；关闭网页不会停止后台平台或正在执行的任务。

## 阅读与启动 Loop

从 Loop 库打开当前版本或草稿，先看用途和流程。点节点打开侧栏。「节点信息」展示简短用途、输入输出契约、执行说明、Skill 和实现方案。「状态转移」集中展示执行状态、转入／转出关系及输入来源。

查看其他方案的规则，从「节点信息」中该方案的「状态转移」进入。规则页标明所属方案。Loop 页面下方的「技术资料」可以查看完整定义、运行配置和随包文档。

网页不编辑名称、参数、默认实现、状态规则或运行安排，也没有保存／发布和“交给 Agent 修改”按钮。Loop 修改通过外部构建 Agent，或下载源文件后编辑并重新打包。接收方运行配置可查看文件路径并在文件中修改，已有 Run 保留快照。

已安装 Loop 的标题旁有「模型设置」，可设置 Loop 默认模型和各 Agent 节点的模型。新 Run 的 Codex 节点优先使用该节点的模型设置，其次使用显式设置的 Loop 默认模型。两项都留空时沿用启动命令中的模型；命令也未指定时使用 `gpt-6.1-sol`。

需要运行时，在 Agent 对话中指定 Loop 和目标，或从命令行调用 `start_run`。在工作台的「运行」中查看 Run。

## 规划托管和 RSI for loop

左侧进入「规划托管」，点「新建规划」，写下安排并选择模型。「开始托管」会在当前平台所在服务器启动 Codex Agent。服务器需要可用的 Codex CLI 和模型访问权限。Agent 把步骤、进展和等待原因写进 Timeline；等待期间可关闭网页。条件读取失败会显示「等待受阻」和具体原因，恢复后继续正常等待。一次性定时任务完成后也可唤醒原规划。平台异常退出后，确认原进程停止，可在原卡片点「确认停止并继续」。需要你决定时，用「补充说明」回复，Agent 会接着执行。

「Loop → RSI for loop」用于回顾同一 Loop 的多次运行。点「发起回顾」，选择 Loop、版本和时间范围，确认覆盖的 Run 数后开始。页面显示最近结论，「查看报告」打开该 Loop 的优化 Timeline。反复回顾沿用这条 Timeline。Agent 按回顾 Skill 保存的手动和定时报告也会更新 RSI 首页。Loop 详情里的「查看此 Loop 的 Run」直接进入筛选好的运行列表。

## 按人查找与整理运行

侧栏按发起人分组并分页。展开“筛选与排序”，可选择人员、Loop、状态、启动日期、最近活跃日期和归档范围。默认最近活跃优先；查看页面和没有变化的轮询不会让运行排到前面。默认将子 Run 收在父 Run 下；指定人员、Loop、状态或日期筛选时会直接列出符合条件的子 Run，搜索同样包含子 Run。

发起人是署名，不是登录。Agent 可以用平台 Skill 的 `profile --name` 记住相同姓名。未署名的旧 Run 可让 Agent 补录，名称和署名通过管理工具修改。

运行页可归档或删除记录；归档仅隐藏于常用列表，不停止工作。删除要求运行已结束且执行／外援已结束，原生 Agent session 与外部产物保留。Loop 库可显示归档并恢复；已有 Run 依赖的版本不能删除，归档后仍能从历史 Run 打开其定义。

## 查看过程与结果

从对话启动后，用 Run 查看执行状态，用 Timeline 查看目标、限制、进度和决策依据。暂停和继续直接作用于同一个 Run。

已安排的工作按任务依赖和状态机推进。Loop 需要判断时可显式声明路由 Agent，由平台记录触发证据与决定。

运行页的任务图和列表展示实际 Task、依赖和等待原因。选中任务后，可从执行记录选择某次尝试，查看参数、输入来源、实现、生命周期和转移历史。

每张任务卡片提供“查看结果”，按执行尝试展示正式输出、文件和失败信息；查看不会重新执行任务。平台按结果结构展示文本、字段和表格，文件结果支持预览或下载。重试保留原 Task 和历次尝试，新一轮安排会产生新 Task。

## 定时任务

从工作台打开“定时任务”，查看当前平台所在机器上的任务、触发方式、下次执行或检查时间，以及最近结果。本机任务在本地平台查看，团队平台托管的任务在团队平台查看。展开“如何登记任务”可找到登记目录，让 Agent 登记后再明确启动。关闭浏览器后任务继续运行，平台重启后需要重新启动任务；查看其他机器的个人任务需打开那台机器的本地平台或使用其本机调度工具。

运行中更新任务登记时，页面会分别显示当前执行的触发方式和下次启动才生效的配置。

## Agent 会话

在任务的执行尝试中选择“查看实时输出”或“打开交互终端”。普通命令提供只读输出；交互终端连接正在运行的同一 CLI，可补充要求、回答提问或发送 Ctrl+C。关闭面板不会停止进程，重新打开可继续查看。

有可恢复原生 session 的 Agent 保留有限实时输出，成功结束后通过原 session 查看完整过程，平台不再存一份重复终端全文。任务的正式结果仍可直接查看；没有可恢复 session 或执行失败时保留必要诊断输出。

通过 Agent 或配置文件为候选实现启用“交互终端”后，主机需支持 PTY；目前支持 macOS/Linux。CLI 的模型、登录、权限及工具配置由使用者负责。终端文字不代替正式结果提交。

Agent 卡片可打开或恢复对应 Run 任务的会话。节点 session 不用于修改 Loop 定义。恢复面板可核对原生 session ID、工作目录、本次要求和恢复命令；没有已记录 ID 时须提供真实身份。Run 必须仍在运行或暂停，CLI 自身的会话文件须保留。旧进程状态未知时，先在主机确认进程及其子进程停止，再使用“已确认旧进程停止”。

## 通知与回复

在「设置 → 通知」管理当前平台的命名出口。运行页只读显示实际出口及通知安排与记录；修改出口由 Agent 配置。

“任务关系”展示等待条件和通知标记，“执行状态机”展示所选实现的实际矩阵。通知安排列出节点、状态或事件、条件和消息；实际通知记录包含脚本与 Agent 临时发出的消息及投递结果。“通知与控制”只读展示安排，并可放行已暂停的任务。

询问可以直接在网页回复，也可以让聊天中的 Agent 代为提交。询问本身不一定暂停运行，需要等待答案的步骤会显示对应等待条件。通知显示已送达不代表用户已读；失败或结果未知时，先核实再重试。

## 配置多机协作

打开「设置 → 团队连接」，填写飞书多维表格链接或本机 NAS 挂载目录。使用已有 NAS 空间时，可展开多团队管理来发现、加入或创建群组。加入群组不会自动开放本机 Agent。

页面分别显示机器 ID 和当前平台 ID。机器 ID 按需生成并保存在本机平台用户环境中；修改显示名称、重启或迁移平台数据不会改变它。同一机器上的多个平台数据库共享机器 ID，但任务寻址彼此独立。复制的平台数据会提示身份冲突；明确“将副本设为独立平台”后可开始新工作，复制过来的 Run 和请求仍是只读历史，不接管原执行。

在「设置 → 接单 Agent」配置具名 Agent 的命令、工作目录和恢复命令，填写主要任务说明并确认开放的群组。可仅开放本机调用，也可只调用别人。成员目录展示主要任务与可用状态；同名成员用机器和 Agent 身份区分。“复制加入说明”可供其他机器加入。

在具名 Agent 的「对应 cc-connect Bot」中设置映射；原群中的确认和结果可优先由对应 Bot 发送，具体仍取决于已配置渠道能力。请求详情可查看状态、结果、日志和通知记录，也可取消或追问。暂停接单或退出群组默认保留已承接工作。


## cc-connect 与 Bot

在“通知出口”的“本机 cc-connect 接入”填写运行中桥接实际配置文件，可执行文件可留空从 PATH 查找。保存后列出 Bot。具名 Agent 编辑时可直接选择 Bot，无需先建通知出口；固定发送群才添加 cc-connect 出口并选择 Bot 和会话。数据目录从配置读取，可填写绝对路径覆盖；此操作不启动或重启 cc-connect。

## 独立 Timeline、会话接续与监控

Timeline 保存当前目标、限制、Loop 定义的业务状态和工作经过。有效要求直接维护，不归档用户聊天原文。侧栏 Timeline 可以查看未启动 Run 的工作；Run 设置区可打开关联 Timeline。可从 Agent 对话启动或接续工作。Run 意外中断后可由新 Run 使用已有 Timeline 接续，原在途实验按原身份观察，不能重复提交。

修改目标或限制后，工具提示 Agent 检查整个 Timeline，特别是运行中的任务，并将结果告诉用户；平台不自动暂停、取消或重排。侧栏监控展示常态及 Run 实例的最近结果、采集时间和错误；停止检查不等于停止实验。脚本可以保留在 Loop 内，也可以通过 Agent 注册到平台复用。具体工具见平台 Skill 的 references/work.md。


## 简洁监控面板

侧栏“监控”打开独立总览，5 秒更新一次。Run 区只显示真实状态、最近进展和需要查看的提示，点击名称进入已有 Run 页面；这里不重复绘制任务图或执行流程。

常态与 Run 外部监控分别展示当前观测值、采集时间和数据有效性。未接入时保持空状态，不预置 GPU、实验或团队专用脚本。Loop 自带 external 观察脚本会在对应 Run 所在页显示简要状态，详细进展仍在原 Run 页面查看。

点击平台注册或内联监控实例可查看最近 240 次采样趋势、参数和原始结果。采集失败、过期与实验失败分别表达，缺失值不补零。脚本可选 metrics=[{key,label,unit}] 声明显示名称和单位；未声明单位不猜测。停止采集只停止该实例的后续检查。脚本库只展示已有注册定义及使用数量，不会因为打开页面而执行脚本。


## 携带 Timeline 到另一个平台

在工作台的 Timeline 详情点击「下载 Timeline」，得到 `.timeline.json` 进度文件。在接收方平台的 Timeline 列表点击「导入 Timeline」，选择文件、查看目标与记录摘要后点击「导入并打开」。导入产生独立 Timeline，不覆盖原工作，也不自动启动任务。

目标、限制、业务状态历史、已保存结果和工作经过都会保留。正在运行、已完成或故障的任务属于 Run 的执行现场，通过 Run 页面或 `read_run(view="snapshot")` 查询，不拼入 Timeline 文件。原平台的训练进程、Agent 会话和执行权限不会迁移，临时安排不随文件携带。模型产物、脚本或日志仍使用引用，使用前应确认接收方可访问。让接收方 Agent 读取这条 Timeline，使用当地相关 Loop 接着推进即可。单个文件最大 20 MiB。
