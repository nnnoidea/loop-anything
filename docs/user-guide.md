# 网页工作台使用说明

网页用于阅读和运行操作。Agent 通过平台工具读写同一份数据；关闭网页不会停止后台平台或正在执行的任务。

## 阅读与启动 Loop

从 Loop 库打开当前版本或草稿，点击流程图中的节点打开侧栏。“节点信息”展示简短用途、输入输出契约、执行说明、Skill 和实现方案；“状态转移”集中展示执行状态、转入／转出关系及输入来源。

查看其他方案的规则，从“节点信息”中该方案的“状态转移”进入；规则页标明所属方案，浏览不会更改默认实现或运行配置。完整方案、脚本、模板、手册与原始 JSON 仍可按需展开查看。

网页不编辑名称、参数、默认实现、状态规则或运行安排，也没有保存／发布和“交给 Agent 修改”按钮。Loop 修改通过外部构建 Agent，或下载源文件后编辑并重新打包。接收方运行配置可查看文件路径并在文件中修改，已有 Run 保留快照。

点击启动时展示配置文件和启动输入，确认启动直接读取当时的 Loop 与运行配置创建 Run，不另建网页 Agent 或准备会话。没有填写必需参数时，由正式创建接口报告；请在配置文件或通过 Agent 补充。

## 按人查找与整理运行

侧栏按发起人分组并分页。展开“筛选与排序”，可选择人员、Loop、状态、启动日期、最近活跃日期和归档范围。默认最近活跃优先；查看页面和没有变化的轮询不会让运行排到前面。默认将子 Run 收在父 Run 下；指定人员、Loop、状态或日期筛选时会直接列出符合条件的子 Run，搜索同样包含子 Run。

启动时填写自己的名字，浏览器会记住；这是署名，不是登录。终端 Agent 可以用平台 Skill 的 `profile --name` 记住相同姓名。未署名的旧 Run 可让 Agent 补录，名称和署名通过管理工具修改。

运行页可归档或删除记录；归档仅隐藏于常用列表，不停止工作。删除要求运行已结束且执行／外援已结束，原生 Agent session 与外部产物保留。Loop 库可显示归档并恢复；已有 Run 依赖的版本不能删除，归档后仍能从历史 Run 打开其定义。

## 查看过程与结果

运行页的任务图和列表展示实际 Task、依赖和等待原因。选中任务后，可从执行记录选择某次尝试，查看参数、输入来源、实现、生命周期和转移历史。

每张任务卡片提供“查看结果”，按执行尝试展示正式输出、文件和失败信息；查看不会重新执行任务。平台按结果结构展示文本、字段和表格，文件结果支持预览或下载。重试保留原 Task 和历次尝试，新一轮安排会产生新 Task。

## 定时任务

从侧栏打开“定时任务”，查看服务器上的任务、触发方式、下次执行或检查时间，以及最近结果。展开“如何登记任务”可以找到服务器登记目录。用 Agent 或 `client local --root <目录> register <任务文件>` 登记，再通过网页或 CLI 启动。关闭浏览器后任务继续运行，服务重启后需要重新启动任务。其他机器上的个人调度用客户端查看。

运行中更新任务登记时，页面会分别显示当前执行的触发方式和下次启动才生效的配置。

## Agent 会话

在任务的执行尝试中选择“查看实时输出”或“打开交互终端”。普通命令提供只读输出；交互终端连接正在运行的同一 CLI，可补充要求、回答提问或发送 Ctrl+C。关闭面板不会停止进程，重新打开可继续查看。

有可恢复原生 session 的 Agent 保留有限实时输出，成功结束后通过原 session 查看完整过程，平台不再存一份重复终端全文。任务的正式结果仍可直接查看；没有可恢复 session 或执行失败时保留必要诊断输出。

通过 Agent 或配置文件为候选实现启用“交互终端”后，主机需支持 PTY；目前支持 macOS/Linux。CLI 的模型、登录、权限及工具配置由使用者负责。终端文字不代替正式结果提交。

Agent 卡片可打开或恢复对应 Run 任务的会话。节点 session 不用于修改 Loop 定义。恢复面板可核对原生 session ID、工作目录、本次要求和恢复命令；没有已记录 ID 时须提供真实身份。Run 必须仍在运行或暂停，CLI 自身的会话文件须保留。旧进程状态未知时，先在主机确认进程及其子进程停止，再使用“已确认旧进程停止”。

## 通知与回复

侧栏“通知出口”管理当前平台的命名出口。运行页只读显示实际出口及通知安排与记录；修改出口由 Agent 配置。

“任务关系”展示等待条件和通知标记，“执行状态机”展示所选实现的实际矩阵。通知安排列出节点、状态或事件、条件和消息；实际通知记录包含脚本与 Agent 临时发出的消息及投递结果。“通知与控制”只读展示安排，并可放行已暂停的任务。

询问可以直接在网页回复，也可以让聊天中的 Agent 代为提交。询问本身不一定暂停运行，需要等待答案的步骤会显示对应等待条件。通知显示已送达不代表用户已读；失败或结果未知时，先核实再重试。

## 配置多机协作

打开“Agent 通信”，先配置各机器已挂载的共享空间，再发现并显式加入或创建群组。加入群组不会自动开放本机 Agent。

页面分别显示机器 ID 和当前工作区 ID。机器 ID 按需生成并保存在本机平台用户环境中；修改显示名称、重启或移动工作区不会改变它。同机多个工作区共享机器 ID，但任务寻址彼此独立。复制来的工作区会提示身份冲突；明确“为副本建立新工作区身份”后可开始新工作，复制过来的 Run 和请求仍是只读历史，不接管原执行。

配置具名 Agent 的命令、工作目录和恢复命令，填写主要任务说明并确认开放的群组。可仅开放本机调用，也可只调用别人。成员目录展示主要任务与可用状态；同名成员用机器和 Agent 身份区分。“复制加入说明”可供其他机器加入。

在具名 Agent 的“对应 Bot 的通知出口”中设置映射；原群中的确认和结果可优先由对应 Bot 发送，具体仍取决于已配置渠道能力。请求详情可查看状态、结果、日志和通知记录，也可取消或追问。暂停接单或退出群组默认保留已承接工作。


## cc-connect 与 Bot

在“通知出口”的“本机 cc-connect 接入”填写运行中桥接实际配置文件，可执行文件可留空从 PATH 查找。保存后列出 Bot。具名 Agent 编辑时可直接选择 Bot，无需先建通知出口；固定发送群才添加 cc-connect 出口并选择 Bot 和会话。数据目录从配置读取，可填写绝对路径覆盖；此操作不启动或重启 cc-connect。
