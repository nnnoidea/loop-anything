# Agent 通信群组与远程执行修改计划

日期：2026-10-09

状态：0.5.2 源码实现及本机验收完成；包含等待外援后恢复原 CLI session。真实 NAS、模型和渠道验收留到安装时。本文件保留原方案，实际交付证据见第 12 节；不授权部署或发送真实通知。

基线：当前工作区 0.4.2，包括尚未提交的终端、原生 session 和审计修复。实施不得覆盖这些改动。

目标：通过统一请求接口调用本机具名 Agent 或群组远端 Agent；本机直接执行，跨机器通过共享 NAS 通信；有无业务 Loop 都能使用。

## 1. 已确认的产品约束

以下是实施必须保留的用户语义。第 3—10 节是据此提出的实现方案；协议字段、工具名和文件布局在落代码前可细化，不得借机改变本节约束。

| 编号 | 已确认约束 | 验收中的反例 |
|---|---|---|
| R1 | 每个节点完成自己的工作；本轮解决远端承接、通信、监控和结果写回。 | 做成新的多 Agent 辩论、成果合并或业务调度框架。 |
| R2 | 各机器安装平台、有自己的身份；平台持续观察自己加入的系统级通信群组。 | 要求每个作者构建一个通信 Loop，或启动 Agent 常驻轮询目录。 |
| R3 | 业务 Loop 可绑定群组；成员知道请求所属 Loop，并可按需读取上下文。 | 远端只能收到一句提示词，或收到无法访问的本机路径。 |
| R4 | 具名 Agent 身份决定承接者；session 只决定新建或继续会话。 | 用 session ID、名称碰巧相同或旧会话所在机器决定认领。 |
| R5 | 必要节点执行与可选外援是不同用途，共用通信机制。 | 把外援回复当成原节点正式输出，或每次外援都改业务图。 |
| R6 | 外援成员可动态增删，不影响 Loop 主体；没有可选外援也应能继续运行。 | 将论文助手在线设置为所有 Run 的启动条件，或无人回复便永久挂起。 |
| R7 | 本地 Agent 默认只由启动该 Run 的平台执行。其他机器只处理明确的群组请求。 | 读取别人的 Loop/Run 后，在远端重新调度它的本地节点。 |
| R8 | 没有 Loop 时，当前对话中的 Agent 也能请求另一台机器上的 Agent。 | 为独立外援伪造业务 Run、Task，或强制请求方注册长期接单身份。 |
| R9 | 发布、认领、进度、结果和接受回执均有持久记录，可重启恢复、去重处理。 | 发出结果即宣称来源已接受；重复消息重复启动进程或提交结果。 |
| R10 | 主动退出立即停止接新任务；失联取消接单资格，保留身份、历史和在途工作。 | 因心跳过期判定任务已停并自动重跑；退出删除历史。 |
| R11 | 飞书/微信用于可配置的协作通知；关键进展默认、按影响告警。 | 依赖聊天消息传输正式任务；逐条发送心跳日志；两端重复通知。 |
| R12 | 能力必须通过界面、实际工具、能力说明、运行上下文和平台 Skill 对 Agent 暴露。 | 只增加后端或工具名字，作者仍需要重写通信、轮询和恢复。 |
| R13 | 可调用对象来自显式开放的本机具名 Agent 目录和获准使用的群组。Loop 使用 Run 绑定范围；无 Loop 使用对话默认或单次指定范围。本地与远端共用请求接口。 | 把任意后台 Agent/CLI 会话当外援；强制本机调用配置 NAS；向所有群组广播；强制调用方注册接单成员。 |

补充边界：节点、Task、执行尝试、具名 Agent、机器/平台实例、CLI session 分别具有自己的身份。一台机器可拥有自己的 Run，同时承接其他平台发布的请求。绑定群组不意味着所有成员获得整个 Run 的修改权。

## 3. 对象、归属和配置

### 3.1 需要持久化的最小对象

| 对象 | 主要内容 |
|---|---|
| 平台实例 | 稳定 instance_id、机器显示名、协议版本；数据库副本不能自动作为第二个同身份在线实例。 |
| 通信群组 | group_id、显示名；每台机器保存自己的 NAS 挂载目录映射。 |
| 具名 Agent | 稳定 agent_id、名称、能力说明、所属实例、本机执行配置、是否开放本机调用。名称不是唯一身份或权限凭证；不要求加入群组才能供本机调用。 |
| 群组成员关系 | Agent 加入哪些群组、是否接单、最近可用状态。退出一个组不等于停用其他组。 |
| 调用上下文 | 本机平台授权的请求方、可选对话关联、默认群组和允许使用的范围；不要求原生 session 或长期接单身份。 |
| 通信请求 | request_id、用途、来源实例、目标/能力要求、本机或群组调用位置、选定群组（本机可为空）、指令、结果要求、可选来源关联、会话策略。 |
| 承接与执行 | 认领提议、来源确认的 assignment_id、执行 Agent/实例、尝试 ID、进程和 session 记录。 |
| 消息和回执 | message_id、请求/执行关联、发送接收方、消息类别、顺序信息、收发与接受状态。 |

通信请求用途至少分为 `node_execution` 和 `assistance`。外援请求的来源可以是 Task、普通对话或独立调用；Loop/Run/Task 全部允许缺省。

来源平台维护请求的正式状态；执行平台维护本机执行事实。共享文件负责传递，不另造一份可被多机任意覆盖的业务 Timeline。

### 3.2 配置建议

- 平台设置：实例身份、群组连接、本机具名 Agent 命令/cwd/CLI/session 配置、本机调用开放开关、各群组接单开关和执行余量。普通 Agent 候选或活跃 CLI 会话不会自动注册进本机目录。
- 本机 Loop 使用设置：选择群组；启动 Run 时可覆盖，Run 保存绑定。修改当前绑定只影响新请求，已发布请求保持原关联。
- 分享包：保留可移植的协作要求；不打包实际 NAS 路径、通知接收位置、运行凭据或某台机器的私有配置。安装方重新绑定本地群组。
- Agent 候选：建议在现有 `kind: agent` 下增加执行位置配置，缺省为本地；群组执行可指定成员或能力条件。字段名在阶段 P0 固定。
- 本轮以远程 Agent 为新交付重点；脚本的现有 command/external/Merlin 路径保持。是否增加 NAS 群组脚本执行配置，作为范围问题明确确认，不默认为新需求。

### 3.3 调用范围与目标选择（已确认补充）

“本机”指当前调用入口所连接的平台实例。工具返回目标所在实例和调用位置，不能凭名称猜测位置；远端节点中的 Agent 通过其执行平台入口发现当地获准调用的成员，Run 来源及群组限制仍须保留。

| 调用方 | 可调用范围从哪里来 |
|---|---|
| Loop 中的 Agent | 本机显式开放且获准调用的具名 Agent，以及该 Run 绑定群组内获准使用的成员。单次目标选择不能绕过 Run 的群组范围。 |
| 无 Loop 的对话 Agent | 本机显式开放且获准调用的具名 Agent；远端使用用户为当前对话设定的默认群组，或本次明确指定的群组。 |

- 本机已加入群组列表用于发现；列出群组不代表本次请求已选中全部群组，也不代表获得其中所有业务内容的权限。
- 无默认群组时，当前 Agent 可列出可用群组供选择；用户已明确唯一且获准的目标时可直接解析。需要消歧时按用户指令及授权选择，不能任取第一个同名 Agent。
- 单次指定群组优先于对话默认，但必须在允许范围内；明确指定的目标不可用时返回状态，不静默跨组寻找替代者。
- 请求创建时固定选定范围、目标标识和位置；之后修改对话默认群组不重路由已有请求。
- 本机调用不依赖群组或 NAS。由同一请求服务持久化请求、校验目标并确认承接，然后直接调度本机配置；不往 NAS 发送一份相同请求。
- 本机和远端都返回 request_id，使用相同的进度、结果、追问、取消和 session 策略；来源与执行平台相同时使用同一本地数据库记录，无需双份镜像。
- 请求方是本机平台授权的调用方，可以只发请求、不接任务。查询和控制按请求访问权限校验；request_id、对话标识和原生 session ID 都不能单独充当授权凭证。

## 4. NAS 通信与承接协议

本节适用于群组跨机器通信。本机具名外援走 3.3 节的直接执行路径，共用请求生命周期、结果校验与防重复启动规则，不要求写共享目录。

### 4.1 收发机制

采用结构化消息文件和双端本地持久收发记录，不共用 SQLite，不要求机器间有 HTTP 直连。初版限定在明确授权的可信共享目录环境，不能把 agent_id 视为防伪认证；多租户或不可信目录不是本轮承诺。

建议逻辑布局为群组说明、成员状态、按实例分区的消息以及产物目录。分区避免多端写同一个文件；消息正文不可变，进度由新消息表达。具体文件命名、版本字段和扫描游标在 P0 固定。

1. 请求或报告先和本机 outbox 在同一事务持久化，再发布到 NAS。
2. 发布时写临时文件再使完整消息可见。真实 NAS 上验证完整性、可见性和崩溃行为；不把本地文件系统测试当成 NAS 保证。
3. 接收端持久记录 message_id，校验来源、群组、关联和版本，再执行业务处理。
4. 本机 inbox 去重与结果写入/待处理操作保持事务一致；只在持久接受后发回执。
5. 未确认消息可重发；接收回执、本地状态和实际副作用的恢复点分别保留。
6. 区分文件收到、业务接受、执行开始、结果产生和结果被接受，不能都叫“成功”。

不承诺任意外部副作用的严格一次执行。尤其记录“已准备启动但不确定进程是否启动”的崩溃窗口，恢复时核对原进程/执行；无法确认则保留未知，不能靠重放请求再启动。

### 4.2 认领建议：来源平台确认后才执行

建议使用“发布 → 成员申请承接 → 来源平台在本地事务中选定一个承接者 → 发布承接确认 → 远端启动”。这是实施建议，不是已经确认的协议字段。

- 指定 Agent 和按能力认领共用这条路径。
- 来源平台是每条请求的确认方，无需再选举整个群组的主服务器，也不依赖跨 NAS 文件锁决定谁获胜。
- 远端只能执行与自己匹配、当前有效的 assignment_id；重复确认不能重复启动。
- 来源暂时离线时，新请求等待确认；已经开始的执行可以继续，报告留在 outbox 等待恢复。
- 取消、退出与迟到确认都要核对执行阶段。承接失联不能凭超时重授已经可能执行过的任务。
- 会话 ID、读取上下文、同名 Agent 和观察到别人的就绪节点都不构成承接确认。

### 4.3 结果、产物和保留

消息携带结构化结果及产物引用，大文件独立存放。引用使用群组内相对资源标识或明确支持的 URI，各机器按本地挂载映射解析；远端绝对路径仅作诊断，不当成可取回产物。

保留请求、承接、状态、回复、结果接受回执、session 关联和操作历史。未确认消息不清理；确认后按可配置保留策略清理传输副本，不误删仍被结果引用的产物。第一轮可先提供显式清理并展示占用，自动保留期限在 P0 明确，避免擅自删历史或无限增长不提示。

## 5. 三条使用路径

### 5.1 正式远程节点

1. 来源 Engine 发现自己拥有的 Run 的节点就绪，所选实现明确为群组 Agent。
2. 在原 Task 执行记录中关联请求，保存任务修订/实现快照；不在远端创建业务 Run。
3. 承接确认后，远端平台用本机配置启动 Agent。保留 Agent 类型、节点上下文和输出契约。
4. 远端通过本机工具入口请求读取/修改；通信桥接把请求送回来源，由原 RunTools 执行权限和版本检查。
5. 正式结果沿用 report_task 及节点校验，来源提交成功后回传接受回执。失败、过期报告和重试继续遵守既有契约。
6. finish 仍只释放本次操作权，不能代替结果完成；来源未确认释放时不能假定已经结束。

来源平台保留正式操作授权，远端使用仅关联本次 assignment 的桥接凭据；不向群组广播平台编辑密码、全局操作令牌或本机模型凭据。不做可调用任意工具的无限制转发。

**本地隔离门槛：** 没有显式群组执行配置就走原本机路径；远端收发服务不能遍历收到的 Run 上下文再调用 tick。NAS 上的 Loop 定义是资料，不是部署/启动指令。

### 5.2 节点中的可选外援

请求方 Agent 在获准的本机具名目录或 Run 绑定群组中发现成员、发出问题和选定上下文；本机由平台直接执行，远端经群组通信。外援提交独立协助结果，请求方自行分析并完成原节点。协助记录挂在节点详情，不添加业务图节点，不因论文助手离线禁止整个 Run 启动。

需要处理两种继续方式：

- 请求方仍工作：可以继续分析，之后查询结果或短时间等待。
- 请求方需要暂停等待：显式持久保存“等待哪些回复”和继续方式，释放/暂存原执行的操作权关系；回复到达后由平台唤醒一次继续处理。

第二种是实际代码缺口。须扩展现有 Task disposition/Agent 唤醒路径，不能仅写一句“回复后继续”。约束：等待不是完成；不占住 CLI 空转；不创建假业务节点；恢复获取新鲜上下文和操作权；回复先于等待登记也不漏唤醒；Run 暂停时保留回复，终止后不再自动启动；重复/迟到回复不重复唤醒或覆盖历史结果。

无适合成员应立即返回不可用；无人承接和结果等待的期限可配置。期限到达表示请求方结束等待，不等于远端进程已停止。固定节点与可选外援不能使用同一套“不可用就跳过”规则。

### 5.3 无 Loop 的独立协助

当前对话 Agent 通过本机平台工具创建请求，来源没有 run_id/task_id；请求方无需注册为长期接单成员。用户关闭对话后请求、日志和结果仍保留，可凭请求 ID 找回。

具体调用顺序：通过平台 Skill 查看本机具名目录及可用群组 → 按本次指令或对话默认确定范围 → 解析目标 Agent 稳定 ID 与位置 → 提交问题、必要上下文和结果要求 → 获得 request_id → 查看/等待结果并用于当前对话。本机目标不需要群组；远端目标需要明确群组。两条路径使用同一调用接口，传输选择由平台承担。

平台自身的网页入口可保存对话默认群组；外部 CLI 使用工具返回的调用上下文引用或每次明确传入群组，具体参数在 P0 固定。不能假定平台自动知道任意 CLI 的原生对话 ID；未提供对话关联的独立调用也必须可用。关闭对话不删除请求，之后由获授权的调用方查询。

调用方式覆盖发送、查进度、取结果、追问、取消。需要提供稳定的返回句柄；支持短等和稍后查询，不把长等待塞入阻塞 HTTP 调用。

普通外部 CLI 对话是否能被自动继续，取决于已明确配置的会话恢复能力。不能默认后台能把消息插入任意正在打开的聊天窗口；无此能力时保存结果并通知，不另开模型会话冒充原对话。

## 6. Agent、session、退出与恢复

### 6.1 会话规则

- 先按 Agent 身份承接，再按请求的会话策略执行；默认新建，明确配置时继续指定会话或允许复用关联会话。
- session 引用包含 CLI 类型、原生 ID 和实际存储/执行环境，不仅是一段 ID 字符串。
- 明确要求继续而记录不可访问时，报告不可用，不能静默新建或选择“最近会话”。
- 活跃会话继续输入、已退出会话重新启动分别处理；同一 session 的重复请求不能同时启动多个进程。
- 查看结果/日志不启动进程，恢复会话不改写已完成业务结果。

终端/会话存储改为能关联“业务执行或通信请求”，保持旧 Run API 与历史记录兼容；不得用假的 Run/Task 填接口参数。NAS 首版交付日志、消息、结果和显式继续会话；逐键 PTY、尺寸变化和延迟体验须单列验证，不以异步消息冒充低延迟终端。

### 6.2 成员状态

保留可接单、忙碌、暂停接单、离线、已退出。平台负责心跳和本机运行状态，不要求模型进程常驻。群组退出停止该组新任务，默认完成在途工作后退出；立即停止需要向来源报告并确认实际进程状态。

心跳超时按观察方记录的最近有效更新判断，不能仅依赖各机器时钟相同。失联保留成员身份，已执行任务显示未知，不自动迁移/重跑。重连先核对原执行及待发送结果，再恢复接单。

平台在线不等于 CLI 认证、模型额度或网络一定可用。能在本地检查的条件明确展示；实际启动配置错误暂停接单并保留原因；一次业务任务失败不自动把整个 Agent 永久移除。

## 7. 飞书、微信与通知记录

使用既有命名通知出口/发送命令/适配器，不新增聊天传输协议。来源平台负责发送，执行端仅回报事实。

默认“关键进展”，另有“仅需处理”和“详细协作”：

- 承接并开始：合并重复的排队/认领通知，说明谁在哪执行什么。
- 外援请求：说明目的及请求方是否正在等待。
- 完成：摘要、产物和详情入口；标明节点正式结果或外援回复。
- 需处理：无人可接、超时、失败、缺输入、权限或会话不可用。
- 受阻/恢复：只有影响具体工作时通知，未知状态不写成失败。

默认不推送心跳、每次轮询、普通工具调用、逐段终端输出、无影响成员上下线。同一状态无变化不持续刷屏。

业务请求沿用 Run 出口；独立请求使用明确选择的本机出口，可继承显式设置的群组默认值。没有配置时留在平台通知区，不猜聊天接收人。当前通知 outbox 属于 Run，需支持请求归属并复用发送、回执、重试逻辑；不能创建假 Run 发送通知。保留已有发送结果未知语义，不承诺第三方网络下严格零重复。

## 8. UI 与 Agent 工具一起交付

### 8.1 界面

1. 平台“通信群组”：加入/退出、NAS 连接检查、成员能力/位置/状态、接单开关、关联 Loop 和请求列表。
2. 本机具名 Agent 目录/配置：名称、稳定身份、CLI/cwd、能力说明、接单余量、会话配置；本机开放调用与各群组接单分别设置。命令由执行机器所有者配置，请求不能任意覆盖；不展示任意运行会话为可调用成员。
3. Loop 使用准备/Run 设置：群组选择与通知出口。节点候选：明确本机或群组执行，显示目标/能力条件。
4. 任务卡片与详情：执行者、机器、远端状态、查看结果/日志/会话；外援请求列表、追问与等待情况。
5. 独立请求详情：无 Loop 也可查看进度、结果、日志、session、取消、通知回执。
6. 独立调用的范围选择：本机目录、对话默认群组、单次群组与目标；显示同名成员所在机器/群组，提示未选择或无可用目标，不要求创建 Loop。

不把内部协议字段和收发队列塞进常用表单；诊断区保留 ID、消息、回执和失败依据。

### 8.2 工具行为（名称为草案）

| 行为 | 使用者与边界 |
|---|---|
| 查看本机目录/群组/成员/能力 | 构建 Agent、节点 Agent、普通对话 Agent；返回稳定身份、所在实例、调用位置、允许范围和可用状态；普通会话不自动公开。 |
| 选择调用范围 | 无 Loop 的调用方可选择对话默认或单次群组；Loop 调用沿用 Run 范围，实际执行时再次检查。 |
| 创建协助请求 | 有授权的当前 Agent；明确本机或群组目标、可选来源，返回统一持久 request_id；不要求请求方成为接单成员。 |
| 读取请求/进度/结果 | 支持游标、增量日志和返回状态，不隐式接单或唤醒。 |
| 追问/取消/选择等待 | 请求方；明确回复到哪个请求/session，不将取消已发出等同于已停止。 |
| 远端报告与上下文工具 | 承接后的限定执行身份；不暴露任意 Run 的写入口。 |
| 群组/本机成员配置 | 用户或明确授权的配置 Agent；与业务接单权限分离。 |

领取、心跳、收发重试由平台承担，不要求每个 Agent 自己调用循环。优先复用现有工具，避免每个消息事件新增一个工具。

更新 `read_capabilities`、作者引导、真实工具 schema、运行上下文、平台 Skill、README 安装/群组连接说明与包交付。必须解释自动行为、启用条件、业务责任和限制，给出正式节点、可选外援、无 Loop 三个例子；外援例子同时覆盖本机目录和群组远端，以及无默认群组时的发现/选择。旧服务未支持时明确拒绝配置，不能静默按本地执行。

## 9. 分阶段实施及停止条件

阶段顺序有依赖。每阶段完成代码、行为测试及对应说明；未完成所有核心阶段不得宣称整项交付。

| 阶段 | 具体产出 | 进入下一阶段的依据 |
|---|---|---|
| P0：固定契约 | 对象和请求/报告 schema、本机目录和调用范围、状态转移、认领确认、重启窗口、等待/唤醒、权限、资源映射、兼容方案；独立实验核查目标 NAS。 | 无需要猜测的主路径；反例和恢复路径均有确定处理。未获得目标 NAS 时保留多机未验证门槛。 |
| P1：系统收发与成员 | 本地数据库增量结构、instance/group/agent 配置、后台收发、心跳、认领、outbox/inbox/回执、退出。 | 两个独立平台进程/数据库通过共享目录完成收发、认领、断线恢复和去重；不触发业务 Loop。 |
| P2：独立外援闭环 | 无 Run 请求、本机具名外援直接执行、远端真实子进程、统一结构化结果、日志/session 归属、查询追问取消。 | 无 NAS/群组时本机调用可用；A 的普通工具客户端选择群组请求 B 并取回结果；均未创建业务 Run。 |
| P3：远程正式节点 | Agent 执行位置、原 Task 请求关联、上下文/工具桥接、报告/finish、权限/版本与过期结果。 | A 的节点在 B 执行，结果由 A 校验推进；B 不启动 A 的其他本地节点；Merlin external 保持。 |
| P4：节点内外援与继续 | 协助记录、上下文选择、持久等待、回复唤醒、会话新建/继续和异常处理。 | 论文外援有/无两种场景均合理；回复竞态、Run 暂停/终止、成员退出不误推进。 |
| P5：通知与产品界面 | Run/独立请求通知归属、三档通知、群组/成员/任务/请求界面；工具与 Skill 同步。 | 网页与 CLI 可操作同一对象；本地通知适配测试通过，真实渠道另行验证。 |
| P6：综合验收与交付 | 回归、双端重启/重复/乱序/断线、真实 NAS 多机及 CLI 验收、打包检查、升级回滚说明。 | 下列验收矩阵有证据，未验证项明确列出；部署和推送按后续授权进行。 |

实现组织：优先增加一个通信领域模块和一个 NAS 收发模块，由 Store/Engine/服务入口接入。暂不引入消息中间件、插件框架或通用 RPC 服务。现有模块仅在职责交叉处提取小型共享函数；避免为全盘统一而重写运行时。

## 10. 验收矩阵

测试验证实际状态、进程启动次数、结果、权限和记录；不以匹配文案或“有接口”证明完成。

| 用例 | 必须观察到的结果 |
|---|---|
| A 的本地节点，B 能看到同群资料 | 只在 A 启动一次；B 不启动，也不为 A 创建 Run。 |
| A/B 各自启动同一 Loop 的不同 Run | 各自本地节点仅在各自实例运行，远程请求不串 Run。 |
| A 节点明确请求 B | B 执行，A 接受合规输出后推进下游；结果查看不唤醒进程。 |
| 两个符合条件成员同时申请承接 | 来源只确认一个 assignment；仅被确认者启动。 |
| 重复请求、确认、进度、结果和回执 | 不重复启动或提交结果，历史可追踪；重发内容冲突明确拒绝。 |
| 半写文件、乱序消息、NAS 临时不可用 | 不处理半条消息、不回退终态，outbox 保留并能恢复。 |
| 启动前后/结果提交前后崩溃 | 已接受结果不丢失；不确定的进程不盲目重启；恢复不重复下游。 |
| 来源离线、执行端仍工作 | 执行和报告可保存；来源恢复后校验接受，不新增业务 Run。 |
| Agent 主动暂停/退出、忙碌、失联、重连 | 接单资格正确，在途未知不自动重派，历史/session 保留。 |
| 节点请求论文外援 | 外援结果是参考资料，原节点由原执行者完成，业务图不增节点。 |
| 没有论文外援/无回应/失败 | 返回可处理状态，请求方可自行完成；不伪造必要节点输出。 |
| 外援回复早到、重复到、迟到 | 等待登记不漏回复，最多一次有效唤醒，不修改已完成结果。 |
| Run 暂停、终止、任务修订变化 | 回复保留，唤醒/正式结果提交按当前状态和版本处理。 |
| 无 Loop 的普通对话请求 | 可发出、查看、取回、追问；不创建假 Loop/Run/Task。 |
| 未加入群组、NAS 不可用时调用本机具名外援 | 通过统一请求接口在本机完成，保留结果/日志/回执语义，不触发 NAS 发布。 |
| Loop Agent 选择本机或绑定群组成员 | 两条路径都可用，群组请求受 Run 范围限制；本机调用不转成远端请求。 |
| 无 Loop、无默认群组、有多个同名成员 | 可发现并明确选择范围/目标，不能任取第一项或广播所有群组。 |
| 单次指定群组、随后修改对话默认 | 本次使用明确指定群组，已有请求不随默认变化重路由。 |
| 当前调用方未注册具名成员、无原生 session ID | 经本机授权后仍可请求和取回结果；只知道 request_id 的未授权调用不能查询或控制。 |
| 普通本地节点/任意 CLI 会话仍在运行 | 不自动进入可调用目录，不因名称或 session 被发现而额外启动。 |
| Agent ID、同名成员、session 可用/不可用 | 正确按稳定身份承接；显式恢复不可用不替换为最近/新会话。 |
| 非匹配 assignment/跨群/越权上下文或结果 | 明确拒绝；NAS 可见性不等于业务写权限。 |
| 跨机器挂载路径不同、资源缺失 | 资源正确解析或明确报缺，原机器路径不被误认为可用。 |
| 通知 Run 与独立请求两种来源 | 明确出口，来源侧去重；外援完成与节点完成分明，无心跳刷屏。 |
| 旧 Loop、external、终端和恢复回归 | 本地默认、Merlin 监控、输出契约、finish、已有历史均保持。 |
| 只给构建 Agent 已安装平台与 Skill | 能发现并使用能力，不需要阅读平台源码或另造 NAS 收发脚本。 |

验收分层：本机双实例/共享临时目录只证明协议与代码行为；真实 NAS 两机器才证明目标部署；真实 CLI/模型测试才证明 Agent 接入；真实飞书/微信回执才证明渠道送达。不能跨层声称完成。

按用户确认的新规则，群组通知入口改为按 instance_id 独立配置，保存本机绑定不会覆盖其他机器。没有聊天来源的新群组请求按每条事件选择动作发生方，再回退本次请求的直接发起方；均无启用入口则记录 skipped，不发外部通知。嵌套外援 C 的动作回退到直接发起方 B，根来源 A 继续保存统一通知账本，不成为子请求的默认兜底。

请求、超时、无人承接等事件由发起方负责；执行、进度、结果与执行失败优先执行方。通知记录 routing 中的动作方、直接来源、实际发送方、绑定 ID 和原因。通知级别默认来自选中入口，显式请求设置优先；缺入口/明确停用才回退，离线、失败和未知送达不切换重发。事件去重不依赖当前绑定档位，改变配置不能重复发送已处理事件。已生成通知及显式重试保留原绑定和发送命令。

旧单一绑定作为该机器入口读取，新请求不再借无关第三台机器统一发送；旧请求保留原创建策略。无群组请求、明确指定出口、业务 lifecycle/notify 沿用原规则。配置与状态界面、公开工具 schema、read_capabilities、Skill 和打包材料同步更新；不发送真实测试消息、不修改已安装运行服务。
